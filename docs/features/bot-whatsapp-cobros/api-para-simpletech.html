Bot de WhatsApp de Cobros — API del CRM

Dos servicios para identificar a un cliente con crédito y mostrarle sus créditos dentro del chat. Este documento tiene todo lo necesario para armar el flujo del bot: contratos, códigos de error, reglas del código de verificación y datos de prueba.

01 Cómo es el flujo

Son dos llamadas. En la primera el cliente se identifica y le llega un código por SMS; en la segunda ese código se valida y, si está bien, se devuelven sus créditos. La validación y la respuesta van juntas: si el código no sirve, no se devuelve nada.

Paso 1
El cliente se identifica
Escribe su NIT, DPI o placa. El bot llama a buscar-cliente con ese dato y con el número desde el que escribe.
›
Paso 2
Le llega un SMS
El CRM manda un código de 4 dígitos al celular registrado del cliente y responde con una referencia, que el bot guarda.
›
Paso 3
Escribe el código
El bot manda referencia + código a creditos. Si es correcto, recibe la lista de créditos para armar el menú.
El código siempre va al celular registrado en el CRM No al número desde el que escribe. Si alguien intenta entrar con el DPI de otra persona, el código le llega al dueño del crédito, no a quien está escribiendo.

02 Autenticación

Las dos llamadas van con la misma llave, en el header:

Authorization: Bearer <API_KEY>
Content-Type: application/json
La llave se entrega por separado No viaja en este documento. Identifica a SimpleTech como integrador, así que no debe quedar en el navegador del cliente ni en repositorios públicos. Sin ella o con una incorrecta, las dos rutas responden 401 NO_AUTORIZADO.

03 Servicio 1 · Buscar cliente y enviar el código

POST /api/bot/cobros/buscar-cliente

Petición

{
  "search": "9900000360101",   // NIT, DPI o placa — sin indicar cuál es
  "telefono": "50257099747"   // número desde el que escribe el cliente
}
CampoTipoDescripción
searchtextoNIT, DPI o placa. El CRM deduce solo cuál es; no hay que decírselo.
telefonotextoEl número del chat. Solo se usa para informar si ya lo teníamos registrado.

Respuesta — cliente encontrado

{
  "success": true,
  "data": {
    "encontrado": true,
    "celEnCrm": false,                  // ¿el número del chat es uno de los suyos?
    "otpEnviado": true,
    "referencia": "c2287206-8f3a-4e21-...",  // GUARDAR: se usa en el paso 3
    "otpEnviadoA": "****9747",           // para decirlo en el chat
    "otpExpiraEnSegundos": 300,
    "cliente": { "nombreCompleto": "Lucía Gómez Prueba" },
    "tipoBusqueda": "dpi"              // "dpi" | "nit" | "placa"
  }
}
Guardar la referencia Es lo único que hace falta conservar entre una llamada y la otra. No hay que volver a mandar el search: esa referencia ya sabe de quién es el código.

Respuesta — no se encontró

{ "success": true, "data": { "encontrado": false } }

Llega como 200, no como error: que el cliente escriba mal su DPI no es una falla técnica. Conviene pedirle que lo intente de nuevo.

Errores posibles

CódigoHTTPCuándo pasa y qué decirle al cliente
BUSQUEDA_INVALIDA400Lo que escribió no parece un NIT, DPI ni placa (por ejemplo, saludó). Pedirle el dato.
PLACA_AMBIGUA400La placa parcial calzó con más de un vehículo. Pedirle la placa completa con la letra inicial.
SIN_TELEFONO_REGISTRADO400El cliente existe pero no tiene celular registrado. Derivar a un agente.
DEMASIADOS_ENVIOS429Pidió códigos muy seguido. Viene data.reintentarEnSegundos con cuánto falta.
OTP_NO_ENVIADO500Falló el envío del SMS. Que reintente en unos minutos.
NO_AUTORIZADO401Falta la API key o está mal.

04 Servicio 2 · Validar el código y traer los créditos

POST /api/bot/cobros/creditos

Hace las dos cosas en una sola llamada: valida el código y, si está bien, devuelve los créditos.

Petición

{
  "referencia": "c2287206-8f3a-4e21-...",  // la del servicio 1
  "otp": "5463"                          // lo que escribió el cliente
}

Respuesta — código correcto

{
  "success": true,
  "data": {
    "creditos": [
      {
        "numeroSifco": "BOT-TEST-002",
        "etiqueta": "Mazda CX-5 2020 · P-902BOT",   // listo para el menú
        "vehiculo": {
          "placa": "P-902BOT",
          "marca": "Mazda",
          "modelo": "CX-5",
          "anio": 2020
        }
      }
    ]
  }
}
CampoDescripción
numeroSifcoIdentificador del crédito. Es el que habrá que mandar en los siguientes pasos del bot (consultar saldo, pagar).
etiquetaTexto ya armado para mostrar en el menú. Si el crédito no tiene vehículo, trae el nombre del cliente.
vehiculoPuede venir en null: hay créditos sin vehículo cargado. En ese caso usar etiqueta.
Un cliente puede tener varios créditos El arreglo puede traer más de uno —incluidos aquellos en los que es codeudor—. Si trae más de uno, hay que mostrar el menú para que elija.

Errores posibles

CódigoHTTPCuándo pasa y qué decirle al cliente
OTP_INVALIDO401Código equivocado. Viene data.intentosRestantes; conviene decírselo.
OTP_VENCIDO401Pasaron más de 5 minutos. Ofrecerle mandar uno nuevo.
OTP_YA_USADO401Ese código ya se usó. Cada código sirve una sola vez.
DEMASIADOS_INTENTOS429Falló 3 veces. Hay que volver al servicio 1 por un código nuevo.
REFERENCIA_INVALIDA401La referencia no existe. Empezar el flujo de nuevo.
Rutear por codigo, no por el texto Los mensajes están en español y pueden ajustarse en cualquier momento; los códigos no cambian. Toda la lógica del bot debería mirar error.codigo.

05 Reglas del código de verificación

ReglaDetalle
Siempre se envíaCoincida o no el número desde el que escribe. Lo que cambia es a dónde se manda, no si se manda.
Formato4 dígitos, por SMS.
Vigencia5 minutos.
Intentos3. Al tercero fallido ya responde DEMASIADOS_INTENTOS, no al cuarto.
Un solo usoValidado una vez, no vuelve a servir.
Reenvíos60 segundos entre uno y otro, máximo 5 por hora por cliente.
Un código nuevo invalida el anteriorSi el cliente pide otro, el viejo deja de funcionar aunque no hayan pasado los 5 minutos.

06 Qué acepta el campo search

No hay que limpiar el dato antes de mandarlo: el CRM normaliza guiones, espacios y mayúsculas.

TipoCómo se reconoceEjemplos que funcionan
DPI13 dígitos9900000360101 · 9900 00036 0101
PlacaTiene letrasP-902BOT · P902BOT · p 902 bot · 902BOT
NITSolo dígitos, y no son 1390000022 · 9000002-2

La respuesta trae tipoBusqueda con lo que dedujo, por si el bot quiere confirmarlo en el chat.

08 Ejemplos con curl

Paso 1 — identificarse

curl -X POST https://tgmt4r4n8pjjqpi7rjqf5lfb.devteamatcci.site/api/bot/cobros/buscar-cliente \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"search":"9900000360101","telefono":"50257099747"}'

Paso 2 — validar el código y traer los créditos

curl -X POST https://tgmt4r4n8pjjqpi7rjqf5lfb.devteamatcci.site/api/bot/cobros/creditos \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"referencia":"LA-QUE-DEVOLVIO-EL-PASO-1","otp":"5463"}'

09 Lo que sigue

Estos dos servicios cubren hasta que el cliente elige un crédito. Lo que viene después —consultar el detalle del crédito, generar link de pago, subir boleta— se irá entregando en la misma forma: un endpoint por gestión, con estos mismos códigos de error.

Cualquier duda sobre el contrato, o si algo responde distinto a lo que dice este documento, avisanos y lo revisamos.
